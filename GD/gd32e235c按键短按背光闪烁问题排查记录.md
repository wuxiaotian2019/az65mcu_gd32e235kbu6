# 按键短按背光闪烁问题排查记录

> 记录时间：2026-09-29
> 适用工程：`az65mcu_gd32e235kbu6 / GD`
> MCU：GD32E235
> 状态：**已定位：该问题与 MCU 代码无关，根因在平台侧 SPL 阶段点亮背光（gpio111）**；本会话 MCU 侧无最终改动，调试过程与中间改动记录如下。

---

## 1. 问题描述

测试部反馈：

- 长按开机键 **约 2~3 秒松手**，会出现**背光亮一下，随即又关机**的现象；
- 且按不足 3 秒时，背光亮起但**无任何显示内容**（纯背光、无画面）；
- 要求：**未真正开机时，不应点亮背光**。

---

## 2. 相关背景

背光早亮功能（见 `LCD背光早亮功能设计说明.md`）：

- MCU 端新增 **PB5** 作为背光使能脚，`lcd_display()` 绘制完首帧后调用 `lcd_backlight_on()` 提前点亮；
- 平台（Unisoc）侧通过 **gpio111** 与 PB5 **并联**驱动 WhiteLED Driver `AW9364DNR` 的 EN 脚。

---

## 3. 排查过程

### 3.1 第一轮假设：MCU 按键判据误判（已证伪，仅修复了一个独立缺陷）

**假设**：`is_long_key_or_nokey_press_power()` 判据 `key_long_press_detected || !key_shot_press_detected` 会把"正按着但未到 3s（key_pressed=1）"误判为"无人按键自动开机"，从而调用 `lcd_display()` 亮背光。

**修改**（[GPIO_init.c `is_long_key_or_nokey_press_power()`](file:///c:/Users/wuxiaotian/github_prj/az65mcu_gd32e235kbu6/GD/src/drivers/gpio/GPIO_init.c)）：

```c
if (!detection_window_active) {
    printf("key_long_press_detected:%d, key_shot_press_detected:%d, key_pressed:%d\n",
           key_long_press_detected, key_shot_press_detected, key_pressed);
    /* power on only for a confirmed long press, or when no key is ever
       touched (auto boot); a short press must not light the backlight */
    if (key_long_press_detected)
        return 1;
    if (!key_shot_press_detected && !key_pressed)
        return 1;
    return 0;
} else {
    return 0;
}
```

**验证结果**：上板实测无效，2~3 秒松手仍会闪背光。

### 3.2 关键推理：亮背光同时有画面，才可能是 MCU 干的

[`lcd_display()`](file:///c:/Users/wuxiaotian/github_prj/az65mcu_gd32e235kbu6/GD/src/drivers/lcd/lcd_display.c#L8-L26) 的执行顺序是**先绘制首帧、后亮背光**：

```c
lcd_init();                          /* 1. LCD 初始化 */
lcd_clear(WHITE);                    /* 2. 刷白屏 */
lcd_draw_image(...);                 /* 3. 绘制 logo —— 首帧就绪 */
lcd_backlight_on();                  /* 4. 之后才亮背光 */
```

全工程仅 [main.c#L78](file:///c:/Users/wuxiaotian/github_prj/az65mcu_gd32e235kbu6/GD/src/main.c#L78) 一处能触发 `lcd_display()`。

**推论**：

| 现象 | 推断 |
|---|---|
| 亮背光 + 有画面 | 可能来自 MCU PB5 |
| **亮背光 + 无画面** | **MCU 的 `lcd_display()` 未执行 → 闪光不是 MCU 干的，来自平台侧 gpio111** |

实测为"纯背光无内容"，**说明闪光来自平台侧**，与 MCU 判据无关——这解释了为何 3.1 的修复无效。

### 3.3 平台侧证据：串口日志确认 SPL 阶段亮背光

通过平台串口日志确认：

- **背光在系统（Unisoc）最早期的 SPL 阶段即被点亮**；
- 平台随后自行按"按键按住时长"裁决：不足 3s 则复位断电，背光随之熄灭——即"亮一下又关机"。

---

## 4. 架构分析：MCU 没有阻止平台上电的能力

对代码逐项确认（[GPIO_init.c](file:///c:/Users/wuxiaotian/github_prj/az65mcu_gd32e235kbu6/GD/src/drivers/gpio/GPIO_init.c#L56-L60)）：

- **PA8 仅是 MCU 的监听脚**（输入模式）：注释 `/* for mcu check pbint status, 0:no powerkey pressed, 1:powerkey pressed */`；
- 平台的电源由 **PMIC/物理按键硬件直连** 上电，**不经过 MCU**；
- 按键一按下 → PMIC 给平台上电 → 平台 SPL 立即启动（远早于 MCU 完成初始化）→ 平台 SPL 点 gpio111 亮背光 → 平台按按住时长裁决开机/断电。

**结论：开机权限在平台/PMIC，MCU 全程只是旁路监听，`is_long_key_or_nokey_press_power()` 只控制 MCU 自己是否 `lcd_display()` 亮背光，对平台是否上电毫无影响。**

```
物理按键按下
  ├→ PMIC 硬件上电 → 平台 SPL 启动 → 平台点 gpio111 背光（SPL 阶段）
  │     └─ 平台按按住时长裁决：≥3s 真开机 / <3s 复位断电
  └→ MCU 用 PA8 旁路监听（仅决定 MCU 是否自己 lcd_display 亮背光 + UART 传输）
```

---

## 5. 结论

1. **该问题与 MCU 代码无关**。背光闪亮发生在平台 SPL 阶段（gpio111），MCU 无任何代码路径参与该时刻的背光控制，也无能力阻止平台上电。
2. 根因在平台侧：**SPL 阶段过早点亮 gpio111 背光**，且平台判定按键时长不足后断电。
3. MCU 侧"提前配置 PB5 拉低钳制"的方案理论上可尝试压住 EN，但因平台 SPL 早于 MCU 完成初始化而**大概率无效**，且并联推挽存在对拉风险，**不建议作为根治手段**。

## 7. 后续建议（平台侧，不在 MCU 代码范围）

1. 平台 **SPL 阶段不点 gpio111**，或把点背光时机**推迟到确认开机成功后**——从根上消除"未开机亮背光"。
2. 若平台必须保留 SPL 提示性亮灯，需与 MCU 端确认并联 IO 模式（避免推挽对拉），并明确亮灭时序分工。
3. MCU 侧保留背光早亮功能本身（PB5 在 `lcd_display()` 首帧就绪后点亮），与平台侧互不干扰。
